# ECert — نظام إدارة مراكز التدريب المتكامل

منصة متكاملة لإدارة **مراكز التدريب**: التسجيلات، الدورات، المدربون، الشهادات (بتحقّق
عام مشفّر)، والإدارة المالية الكاملة (فواتير، دفعات، أقساط، عهدة، صندوق، استردادات،
تقارير، تدقيق)، إضافةً إلى **موقع عام** بمحتوى قابل للتحرير الكامل من لوحة الإدارة.

النظام **عربي بالكامل (RTL)**، بواجهة إدارية حديثة مبنية على Bootstrap 5، وقاعدة بيانات
**MySQL / MariaDB**، ويعمل على **.NET 10**.

> **English TL;DR:** ECert is a full Arabic (RTL) training-center management system built
> with ASP.NET Core MVC on .NET 10, EF Core + MySQL/MariaDB, fine-grained RBAC, a
> ledger-based double-checkable finance module, tamper-evident (SHA-256 hash-chain) audit
> logs, and publicly verifiable certificates/receipts signed with HMAC. Docker-ready.

## 1. نظرة عامة

**ECert** يغطّي دورة العمل الكاملة لمركز تدريب:

- زائر يسجّل في دورة من **الموقع العام** ← يُراجَع الطلب ويُقبل ← تُنشأ **فاتورة** تلقائياً
  ← تُسجَّل **دفعة** (تُضاف إلى **عهدة** المحصّل) ← تُورَّد العهدة إلى **الصندوق الرئيسي**
  ← تُصدر **شهادة** لها رقم فريد ورابط تحقّق عام (QR/Barcode).
- وكل حركة مالية أو إدارية تُقيَّد في **سجل تدقيق مُوقَّع بسلسلة تجزئات (Hash Chain)** لا
  يمكن التلاعب به دون كشفه.

**الفكرة المحورية:** كل الأرصدة في النظام **مُشتقّة من دفاتر (Ledgers) قابلة للتتبّع**، وليست
حقولاً مخزّنة قابلة للتعديل. لا يوجد «حقل رصيد صندوق» يُحدَّث يدوياً، بل يُحسب وقت الاستعلام
من مجموع الحركات — وهذا ما يجعل النظام **قابلاً للتوفيق (Reconcilable)** ومقاوماً للتلاعب.

## 2. المزايا الرئيسية

### إدارة التدريب
- **التسجيلات**: مراجعة، قبول/رفض، إعادة فتح، أرشفة/استعادة، إعفاء مالي، إجراءات جماعية،
  استيراد وتصدير Excel.
- **الدورات**: ست حالات (`Draft`, `Published`, `OpenForRegistration`, `InProgress`,
  `Completed`, `Archived`)، مدربون متعددون، جهات داعمة (شعار/توقيع)، خصومات، قوالب شهادات،
  صورة، استيراد/تصدير.
- **الفئات والمدربون**: مع منتقي أيقونات جاهز ولوحة توقيع مباشر (رسم/رفع).
- **الشهادات**: إصدار فردي/جماعي، تصاميم مرئية (WYSIWYG) بحقول ديناميكية و QR/باركود وتوقيعات،
  واستيراد الشهادات القديمة من Excel.
- **البيانات الجامعية**: هيكل هرمي (جامعة ← كلية ← تخصص ← مستوى) ونقاط AJAX عامة للنماذج المترابطة.
- **مفاتيح الهواتف**: تحقق من البادئات وأطوال الأرقام لكل دولة.

### الإدارة المالية
- **الفواتير** بحالات (`Unpaid`, `PartiallyPaid`, `Paid`, `Cancelled`) وإلغاء/استعادة.
- **الدفعات** (نقد/تحويل/محفظة/بطاقة) مع **رقم سند إجباري للطرق الإلكترونية**.
- **الأقساط والخطط** مع توزيع الدفعات زمنياً وحالة كل قسط مُشتقّة من الدفعات الفعلية.
- **عهدة الموظف والتوريد** بطلبات توريد يعتمدها مدير النظام، و**لا عهدة سالبة أبداً**.
- **المتأخرات** وكشوف الحساب وأعمار المتأخرات.
- **الاستردادات** بحد اعتماد قابل للضبط (تتجاوز الحد ⇒ بانتظار اعتماد مدير النظام).
- **المصروفات** ببنودها وموافقاتها.
- **الصندوق الرئيسي** (مدير النظام فقط) مع سحوبات وإقفال الفترة.
- **التقارير**: إيرادات الدورات، التدفق النقدي، قائمة الدخل، أعمار المتأخرات، المطابقة النقدية.
- **سجل التدقيق المالي** و**فحص سلامة السلسلة**.

### الموقع العام (محتوى قابل للتحرير)
- صفحة رئيسية بأقسام قابلة للإظهار/الترتيب (شرائح، نصوص متحركة، إحصائيات، فئات، دورات،
  أخبار، مدربون، شهادات، شركاء).
- من نحن، اتصل بنا، سياسة الخصوصية، الدورات العامة، الأخبار.
- **التسجيل العام** (مع مصيدة روبوتات Honeypot و Turnstile وتحديد معدل).
- **التحقق العام** من الشهادة (`/Certificates/Verify`, `/v/{publicId}`) ومن السند
  (`/r/{publicId}`) بدون تسجيل دخول.

### إدارة النظام
- **مستخدمون وأدوار بصلاحيات دقيقة** (28 صلاحية) وقوالب أدوار جاهزة.
- **نطاق الدورات** للعزل بين الفروع/المشرفين.
- **سجل العمليات** المُوقَّع بسلسلة تجزئات.
- **إعدادات الأمان والنسخ الاحتياطي** (تليجرام، تشفير AES-256، سياسة الحظر، 2FA، مهلة الخمول).
- **إعدادات مالية** (العملة، حد اعتماد الاسترداد، إقفال الفترة).

## 4. البنية المعمارية

```
┌─────────────────────────────────────────────────────────────────────┐
│                          المتصفح (RTL)                              │
│   الموقع العام  ──────────────  لوحة الإدارة (Bootstrap 5 RTL)      │
└──────────────────────────────┬──────────────────────────────────────┘
                               │ HTTPS (TLS يُنهى عند الوكيل العكسي)
┌──────────────────────────────▼──────────────────────────────────────┐
│                      ASP.NET Core MVC (.NET 10)                     │
│  Middleware: ForwardedHeaders → HSTS/CSP → StaticFiles → RateLimiter │
│              → Authentication → MustChangePassword → Authorization  │
│                                                                     │
│  Controllers (36 MVC + 9 REST API)  ⇄  Services (66)  ⇄  EF Core    │
│                                                                     │
│  BackgroundService: النسخ الاحتياطي المشفّر اليومي                    │
│  Startup: EnsureCreated + *SchemaMigrationService (ترقيات idempotent)│
│           + DbSeeder (البيانات الأساسية)                             │
└──────────────────────────────┬──────────────────────────────────────┘
                               │ EF Core / MySqlConnector
┌──────────────────────────────▼──────────────────────────────────────┐
│                        MySQL / MariaDB                              │
│  جداول النموذج + DataProtectionKeys + سجلات التدقيق (Hash Chain)     │
└─────────────────────────────────────────────────────────────────────┘
```

### ملاحظات معمارية مهمة

- **بدء التشغيل (Bootstrap):** عند الإقلاع يضمن التطبيق وجود المخطط عبر `EnsureCreated()`،
  ثم ينشئ جدول `DataProtectionKeys`، ثم يُشغّل سلسلة **خدمات ترقية المخطط** idempotent
  (`*SchemaMigrationService`) التي تضيف الأعمدة/الجداول الناقصة، ثم يُشغّل `DbSeeder`
  للبيانات الأساسية **دون الكتابة فوق الموجود**.
  > **لا توجد ملفات EF Core Migrations تقليدية**؛ آلية الترقية مخصّصة (SQL idempotent).
  > **الترتيب مهم:** خدمات إنشاء الأعمدة يجب أن تسبق أي خدمة تحمّل الكيان المقابل.

- **الجلسة عبر كوكيز مُشفَّر**، ومفاتيح Data Protection تُحفظ في قاعدة البيانات لتبقى الجلسات
  صالحة عبر عمليات النشر وإعادة بناء الحاويات.

- **الصلاحيات مُحمَّلة في الكوكيز**؛ لذلك تغيير صلاحيات دور يسري عند **إعادة تسجيل الدخول**.

- **الرؤوس الممرَّرة (ForwardedHeaders)** محدودة بـ **قفزة واحدة** (`ForwardLimit = 1`) لأن
  الوكيل ينهي TLS عند الحدود، فلا يمكن للمتصل تزوير عنوانه بإضافة رؤوس.

## 6. الأدوار والصلاحيات (RBAC) ونطاق الدورات

يعتمد النظام على **صلاحيات دقيقة (Fine-grained Permissions)** لا على أدوار ثابتة. يوجد **دور
مدمج واحد فقط** هو `SuperAdmin`، وكل ما عداه أدوار مخصّصة ينشئها مدير النظام.

- **28 صلاحية** موزّعة على مجموعات (إدارة التدريب، الشهادات، المالية، المحتوى، النظام).
- **قوالب أدوار جاهزة (Presets):** محاسب، محصّل رسوم، مشرف تسجيلات، مشرف تدريب، مسؤول شهادات،
  محرر محتوى، مدقق أمني.
- **صلاحيات حصرية لمدير النظام (SuperAdminOnly):** `manage-roles`، `manage-finance-settings`،
  `manage-security-settings`.
- **قسم الصندوق (`Cashbox`) محظور على غير مدير النظام** ولا تفتحه أي صلاحية.
- **قاعدة معمارية:** أي Controller بلا مدخل في `AdminPermissions.SectionAccess` يُعتبر
  **SuperAdmin-only تلقائياً**، فلا تصبح صفحة جديدة عامة بالخطأ. اختبار
  `AdminPermissionsCatalogTests` يحرس الاتجاهين (كل صلاحية تفتح قسماً، وكل قسم مفتوح).

### نطاق الدورات (Course Scope)

آلية **العزل بين الفروع/المشرفين**:

- **غير مقيّد:** بلا أي إسناد ⇒ يرى **كل** الدورات.
- **مقيّد:** لديه إسنادات دورات و/أو فئات ⇒ يرى نطاقه فقط، ويُرفض أي وصول خارجه.
- **إسناد فئة** يمنح كل دوراتها **الحالية والمستقبلية**.
- **«لا شيء مُمنوح» ≠ «غير مقيّد»:** من مُنح فئةً فارغة يحمل علامة تقييد صريحة، فلا يُرقّى
  خطأً إلى «الكل».
- من يُنشئ مستخدماً بغير صلاحية مدير النظام **يرث نطاقه**، فلا يمنح حساباً أوسع منه.
- التقييد يُفرض بـ `.InScope(User)` على كل استعلام (تسجيلات، فواتير، دفعات، تقارير، لوحة
  تحكم، صندوق، شهادات، واجهات API).

## 7. الوحدة المالية: القواعد المعمارية

| القاعدة | التفصيل |
|---------|---------|
| **كل رصيد مُشتقّ من دفتر** | لا حقل رصيد مخزّن؛ الأرصدة تُحسب من مجموع الحركات. |
| **المسار الوحيد لتمويل الصندوق** | لا تدخل الأموال الصندوق إلا عبر **توريد عهدة** يعتمده مدير النظام. |
| **الأموال المحصّلة تهبط في عهدة المحصّل** | كل دفعة تدخل عهدة من سجّلها؛ الاسترداد يخصم من عهدته. |
| **لا عهدة سالبة أبداً** | لا يصبح رصيد عهدة الموظف سالباً. |
| **الاسترداد حركة جديدة لا حذف** | يُنشئ حركة مؤرّخة تقلّل رصيد الفاتورة وتخصم العهدة. |
| **إقفال الفترة يمنع الكتابة** | أي حركة (دفعة/استرداد/سحب/توريد) داخل فترة مقفلة تُرفض. |
| **كل حركة مُدقّقة** | كل حركة تُضاف لسجل التدقيق المالي المُذيَّل بـ Hash Chain. |
| **قفل الصفوف** | العمليات المالية الحساسة تستخدم `SELECT ... FOR UPDATE` لمنع التزاحم (race conditions). |

**حد اعتماد الاسترداد:** أي استرداد يتجاوز الحد المُعدّ في الإعدادات المالية يُسجَّل بحالة
**بانتظار الاعتماد** ولا يحرّك أي مال حتى يعتمده مدير النظام.

**المتاح للاسترداد** = صافي مدفوع الفاتورة (الدفعات − الاستردادات المعتمدة) ناقص أي استردادات
معلّقة، حتى لا يتجاوز استردادان معلّقان الحدّ معاً.

## 8. الشهادات والتحقق العام

- كل شهادة تحصل على **رقم فريد**، **PublicId**، **رمز تحقق**، وتوقيع **HMAC**.
- **رابط تحقق عام:** `/v/{publicId}?sig=...` (يُستخدم من QR/Barcode)، بدون تسجيل دخول.
- **صورة QR:** `/Certificates/QrImage?publicId=...&sig=...`.
- **التحقق اليدوي:** `/Certificates/Verify` (يُقبل رقم الشهادة أو رمز التحقق).
- **تصاميم الشهادات:** محرر مرئي بعناصر (نص ثابت، حقل ديناميكي، QR، باركود، شعار/توقيع شريك،
  توقيع مدرب، فاصل) وإعدادات لوحة كاملة.
- **استيراد الشهادات القديمة** من Excel مع معاينة قابلة للتعديل ودمج ذكي للدورات.
- **التحقق العام من السندات:** `/r/{publicId}?sig=...` يعرض الحد الأدنى اللازم للتحقق فقط.
- **بطاقات المشاركة (OG):** `/share/certificate/{publicId}.png` و`/share/site.png` لمعاينات
  غنية عند مشاركة الروابط في تطبيقات المحادثة.

> **قاعدة الإصدار:** لا تُصدَر الشهادة إلا لتسجيل بحالة `Accepted` ودورة بحالة `Completed`
> وبلا شهادة سابقة.

## 9. الأمان

- **كلمات المرور:** BCrypt (Hash فقط، لا تُخزَّن كلمة المرور الأصلية أبداً).
- **المصادقة الثنائية (2FA):** رمز OTP عبر تليجرام، صالح **5 دقائق**، **5 محاولات**، يُستهلك
  عند أول استخدام.
- **حماية تسجيل الدخول:** تأخير تدريجي/حظر مؤقت بعد عدد محاولات فاشلة قابل للضبط (بلا قفل دائم)،
  مع تنبيه تلقائي لقناة تليجرام عند تجاوز الحد.
- **تحديد المعدل (Rate Limiting):** التسجيل العام 3/دقيقة، التحقق العام 20/دقيقة، دخول الإدارة
  10/دقيقة (لكل عنوان).
- **مهلة الخمول:** تُنهى الجلسة بعد `IdleTimeoutMinutes` من عدم النشاط (يُفحص داخل الكوكيز).
- **رؤوس الأمان:** CSP، HSTS، `X-Frame-Options: DENY`، `X-Content-Type-Options: nosniff`،
  `Referrer-Policy`.
- **CSRF:** رمز مكافحة التزوير على كل نماذج وإجراءات POST (`[ValidateAntiForgeryToken]`).
- **مصيدة الروبوتات (Honeypot)** + **Cloudflare Turnstile** (اختياري) على النماذج العامة.
- **التحقق من الرفع:** فحص التوقيع الثنائي (magic bytes) — يُرفض SVG/HTML الخبيث، بحد أقصى 5MB
  للصور و10MB لملفات Excel.
- **سلسلة تجزئات SHA-256** على سجلَي العمليات والتدقيق المالي لكشف أي تلاعب، مع صفحة **فحص سلامة**.
- **حماية مفاتيح الجلسة:** Data Protection مُخزَّن في قاعدة البيانات ومُشفَّر.

> ⚠️ **تنبيه تشغيلي:** لا تغيّر `CERT_HMAC_SECRET` بعد إصدار شهادات؛ تغييره يُفسد التحقق من
> التوقيعات الحالية.

## 11. المتغيرات البيئية وإعدادات التشغيل

| المتغير | إلزامي | الوصف |
|---------|:------:|-------|
| `ConnectionStrings__MySqlConnection` أو `DATABASE_URL` | ✅ | اتصال MySQL/MariaDB (صيغة ADO.NET أو `mysql://`). |
| `CERT_HMAC_SECRET` | ✅ (مُستحسن) | سر توقيع الشهادات/السندات. **لا تغيّره بعد الإصدار.** |
| `PUBLIC_BASE_URL` | مُستحسن | العنوان العام لبناء روابط التحقق/QR خلف وكيل عكسي. |
| `ECERT_BOOTSTRAP_PASSWORD` | اختياري | كلمة المرور الأولية لحسابات البذرة (وإلا تُولَّد عشوائياً وتُسجَّل مرة واحدة). |
| `ECERT_RESET_ADMIN_PASSWORD` | اختياري | إعادة تعيين كلمة مرور `admin` مؤقتاً (يُفضّل إلغاؤه بعد الاستخدام). |
| `TURNSTILE_SITE_KEY` / `TURNSTILE_SECRET_KEY` | اختياري | تفعيل Cloudflare Turnstile على النماذج العامة. |
| `Institution:Name` | اختياري | اسم المركز على السندات (افتراضي «مركز التدريب»). |
| `ASPNETCORE_ENVIRONMENT` | — | `Production` / `Development`. |
| `PORT` | — | يُحترم تلقائياً (منصات مثل Railway). |

**ملاحظات:**
- الصيغ المدعومة للاتصال: `ConnectionStrings:MySqlConnection`، `ConnectionStrings__MySqlConnection`،
  `MySqlConnection`، أو `DATABASE_URL`. وتُقبل صيغتا ADO.NET و`mysql://`/`mariadb://`.
- إعدادات الأمان الحسّاسة (توكن البوت، مفاتيح النسخ، سياسة الحظر) تُدار **من داخل النظام** عبر
  `/SecuritySettings` وتُقرأ ديناميكياً من قاعدة البيانات (تسري فوراً بلا إعادة نشر).

## 12. التشغيل السريع

### المتطلبات
- **.NET SDK 10**
- **MySQL 8** أو **MariaDB 10.6+**

### الخطوات

```bash
# 1) إنشاء قاعدة البيانات ومستخدمها
mysql -u root -p <<'SQL'
CREATE DATABASE ecert CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER 'ecert'@'%' IDENTIFIED BY 'ecert_pass';
GRANT ALL PRIVILEGES ON ecert.* TO 'ecert'@'%';
FLUSH PRIVILEGES;
SQL

# 2) ضبط الاتصال (متغيرات بيئة بدل كتابتها في الملفات)
export ConnectionStrings__MySqlConnection="Server=127.0.0.1;Port=3306;Database=ecert;User ID=ecert;Password=ecert_pass;SslMode=Preferred;AllowPublicKeyRetrieval=True"
export CERT_HMAC_SECRET="$(openssl rand -hex 32)"
export PUBLIC_BASE_URL="http://localhost:5000"
export ECERT_BOOTSTRAP_PASSWORD="ChangeMe@12345"

# 3) التشغيل (يُنشئ المخطط والبيانات الأساسية تلقائياً عند أول إقلاع)
dotnet run --project ECert/ECert.csproj
```

افتح المتصفح على `http://localhost:5000`، ثم سجّل الدخول:

| الحساب | كلمة المرور |
|--------|-------------|
| `admin` | قيمة `ECERT_BOOTSTRAP_PASSWORD` (أو الكلمة العشوائية المسجّلة في الطرفية) |

> سيُطلب **تغيير كلمة المرور إجبارياً** عند أول دخول. صحّة النظام متاحة على `/health`.

### عبر Docker

```bash
docker build -t ecert .
docker run -d --name ecert -p 10000:10000 \
  -e ConnectionStrings__MySqlConnection="Server=db;Port=3306;Database=ecert;User ID=ecert;Password=ecert_pass;SslMode=None;AllowPublicKeyRetrieval=True" \
  -e CERT_HMAC_SECRET="$(openssl rand -hex 32)" \
  -e PUBLIC_BASE_URL="https://ecert.example.com" \
  -e ECERT_BOOTSTRAP_PASSWORD="ChangeMe@12345" \
  -v ecert_uploads:/app/wwwroot/uploads \
  -v ecert_qrcodes:/app/wwwroot/qrcodes \
  ecert
```

## 14. النشر

- **Docker:** `Dockerfile` متعدد المراحل (SDK → runtime) مع `docker-entrypoint.sh` الذي يضبط
  ملكية مجلدات الرفع عند تشغيل الحاوية كـ root ثم يهبط لمستخدم غير مميّز (`app`) قبل تشغيل
  التطبيق، ويحترم `PORT`.
- **المنصة الأصلية:** مُهيّأ لـ **Railway** (منفذ `10000`، فحص `/health`، أحجام دائمة للرفع).
- **سيرفر خاص:** راجع **[docs/DEPLOYMENT-AR.md](docs/DEPLOYMENT-AR.md)** — دليل تقني كامل
  (Nginx، TLS، systemd، النسخ الاحتياطي، الترقية، استكشاف الأخطاء).

> **مهم:** يجب تثبيت `mysql-client` (لتوفير `mysqldump`) داخل حاوية/بيئة التشغيل ليعمل
> **النسخ الاحتياطي المشفّر اليومي**؛ فهو يُشغّل `mysqldump` ويُشفّر الناتج (AES-256) ويرفعه
> لقناة تليجرام.

## 15. النسخ الاحتياطي والاستعادة

- **نسخ احتياطي يومي مشفّر** عبر `BackgroundService` (الساعة قابلة للضبط في `/SecuritySettings`).
  التدفّق: `mysqldump` → ضغط/تشفير AES-256 → رفع إلى قناة تليجرام (لا تُكتب نسخة على قرص الحاوية).
- **تشغيل نسخة فورية** من صفحة `/SecuritySettings` (**تشغيل نسخة الآن**).
- **تبديل/استعادة قاعدة البيانات:** راجع [docs/DATABASE_RECOVERY.md](docs/DATABASE_RECOVERY.md).

```bash
# استعادة نسخة SQL على قاعدة فارغة
mysql --host=HOST --port=PORT --user=USER --password DATABASE < ecert_full.sql
```

> احتفظ بنسخة SQL خارج السيرفر، ولا تضع ملف النسخة في المستودع العام. خزّن
> `MySqlConnection` و`CERT_HMAC_SECRET` في متغيرات البيئة فقط، ودوّر أي مفتاح ظهر في محادثة أو سجل.
