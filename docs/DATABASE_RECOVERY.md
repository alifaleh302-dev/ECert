# ECert Database Recovery

## التشغيل على قاعدة بيانات جديدة

التطبيق يستخدم MySQL/MariaDB عبر `MySqlConnection` (أو `DATABASE_URL`) ولا يعتمد على ملفات قاعدة بيانات داخل الحاوية.
عند توجيه متغير الاتصال إلى قاعدة فارغة، يقوم التطبيق عند بدء التشغيل بـ:

1. `EnsureCreated()` لإنشاء جداول نموذج Entity Framework لأول مرة.
2. إنشاء جدول `DataProtectionKeys`.
3. تشغيل ترقيات مخطط idempotent القديمة والجديدة (`*SchemaMigrationService`) لإضافة الأعمدة والجداول الناقصة.
4. تشغيل البيانات الأساسية دون الكتابة فوق البيانات الموجودة.

لا توجد ملفات EF Core migrations تقليدية في المستودع؛ هذه آلية bootstrap/ترقية SQL مخصصة. لذلك يجب الاحتفاظ بنسخة احتياطية قبل أي تبديل أو ترقية.

## تبديل قاعدة البيانات

1. أنشئ قاعدة MySQL/MariaDB جديدة فارغة.
2. في Railway > ECert service > Variables عدّل **فقط** `MySqlConnection` إلى رابط القاعدة الجديدة. يمكن أيضاً استخدام صيغة `mysql://...` أو صيغة ADO.NET.
3. اترك `CERT_HMAC_SECRET` كما هو؛ تغييره يفسد التحقق من توقيعات الشهادات الحالية.
4. أعد النشر وانتظر نجاح الإقلاع.
5. تحقق من الصفحة الرئيسية وتسجيل الدخول، ثم استورد النسخة الاحتياطية إذا كان المطلوب الاحتفاظ بالبيانات.

## استعادة نسخة SQL

نفّذ النسخة على قاعدة فارغة باستخدام عميل MySQL:

```bash
mysql --host=HOST --port=PORT --user=USER --password DATABASE < ecert_full.sql
```

ثم وجّه `MySqlConnection` إلى القاعدة المستعادة وأعد النشر. النسخة تتضمن المخطط والبيانات ومفاتيح حماية Data Protection؛ لا تضع ملف النسخة في المستودع العام.

## احتياطات

- لا تحذف جداول أو أعمدة قديمة تلقائياً أثناء الإقلاع؛ الترقيات التلقائية تضيف وتعدّل فقط عند الحاجة.
- احتفظ بنسخة SQL خارج Railway قبل انتهاء أي قاعدة مجانية.
- خزّن `MySqlConnection` و`CERT_HMAC_SECRET` في متغيرات Railway فقط، ودوّر أي مفاتيح ظهرت في محادثة أو سجل طرفي.
- بيانات المستخدمين تتضمن `PasswordHash` فقط، وليست كلمات المرور الأصلية؛ لا تشارك ملف users CSV علناً.
